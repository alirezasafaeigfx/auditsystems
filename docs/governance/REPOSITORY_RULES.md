# Audit project rules — complete quality and truthful execution

Updated: 2026-08-31. Entry point: [AGENTS.md](../../AGENTS.md). Selector: [canonical roadmap](../roadmaps/AUDIT_PUBLIC_EXPERIENCE.md). Product standard: [shared quality/growth contract](../strategy/PAIRED_QUALITY_GROWTH_CONTRACT.md). Existing operational/security runbooks remain binding for their actual scope.

## Outcome and scope

Deliver the complete admitted outcome with high quality: usable UI/UX, natural Persian, accurate and useful checks, reliable failure recovery, accessibility/performance, technical SEO and useful content. The smallest complete solution avoids unrelated work; it never means token edits, default-template visuals or omitting required error/mobile states.

Coordinate only the two named repositories. Keep Audit PostgreSQL/custom CSS, current auth/worker/report architecture and independent releases. No third product, framework/DB/CMS rewrite, paid vendor, live tracking, campaign, commercial promise or runtime operation is authorized merely by these rules.

## Source, language and data truth

First explain the visitor's problem, benefit, limits and next action. Use plain respectful Persian on headings, controls, validations, queue/report status, errors and PDF content; technical detail remains optional. EN preserves meaning and navigation. Primary labels must not require understanding internal enums or engineering language.

One authorized result policy applies across HTML/RSC/API/PDF/comparison. Unknown/failed measurement is not passed; more failures under the same policy/coverage cannot improve a score. Preserve explicit sample/legacy labels and scoring version. Do not rewrite old reports to hide contradictions.

Protect customer data, report tokens, passwords and private target URLs in code, logs, screenshots, analytics and cross-domain links. Test access, SSRF, failure/retry and scoring only with disposable data/targets. Do not use public token guesses or real submissions as test fixtures.

## Search and measurement

Correct canonical/locale/robots/sitemap/visible structured data and useful original content are required. They do not establish Google indexing or top rank. Never use robots/noindex as access control, publish private reports for SEO, create doorway/duplicate intent pages, buy links, fake ratings or mass-publish filler.

Keep a versioned, source-backed intent cohort and dated scorecard with denominators. Separate lab from field, emulated from real device, expert review from actual participants, navigation from completed audit and observation from causation. Missing data remains missing; a rank-one claim must be narrow and supported. No single score certifies “best in the world.”

## Execution, review and autonomy

Use the [paired execution prompt](../../prompts/codex/PAIRED_SITES_YOLO_LOOP.md), relevant [task cards](../execution/QUALITY_GROWTH_SPRINTS.md) and [ledger](../execution/QUALITY_WORK_LEDGER.md). One coordinator owns integration/status; active workers own non-overlapping paths. Preserve dirty work and public history, use PRs, never force-push, invent task IDs or weaken scope/security checks.

Behavior needs meaningful tests and actual built-route verification; UI needs inspected screenshots/recordings and all required states. Validate current mandatory checks even if main is unprotected. Docs-only work needs full diff, links, source/consistency/privacy checks and independent document review; app benchmarks and owner visual review are not relevant to a prose-only unit. Do not falsely report unrun local tests as passed. Required hosted checks remain effective.

Every claim needs exact candidate/scope and retrievable sanitized evidence. Independent review must have a real separate reviewer, not a self-declared label. Prepare complete owner visual comparison before requesting disposition. Code accepted, runtime verified, field observed and leadership demonstrated are separate verdicts; unavailable evidence is never PASS.

Resolve routine choices and continue safe ready tasks automatically. After repeated unchanged failures, diagnose and block that action with a retry trigger, then continue elsewhere. Checkpoint exact next action before limits. Do not keep running for future traffic, create timers, re-plan completed work or simulate progress. Preserve actual current authorization, data, payment, deployment and repository gates; ask only when a concrete prepared result genuinely needs missing authority/input.
