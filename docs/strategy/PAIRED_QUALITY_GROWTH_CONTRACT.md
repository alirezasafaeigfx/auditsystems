هدف مشترک: هر دو سایت از نظر طراحی، تجربهٔ کاربری، فارسی روان، کاربرد واقعی، سرعت، اعتماد و سئو در سطح بهترین نمونه‌های جهان باشند و برای نیازهای مشخص مخاطب ایرانی به انتخاب اول حوزهٔ خود تبدیل شوند.

Rank one is a competitive ambition, not a guaranteed deliverable or a fact about either site today. Separate four verdicts: **implementation accepted**, **release verified**, **field outcomes observed**, and **search leadership demonstrated**. Passing the first two never automatically passes the last two. There is no honest global “best website” certificate or single ranking for a whole industry.

ASDEV retains its distinctive interactive/spatial signature; Audit prioritizes clear input, reliable processing and readable results. ## Quality acceptance matrix

Numbers below are project targets, not measurements. A missing source is UNVERIFIED, not zero, not PASS.

| Dimension | Required outcome | Evidence that can support acceptance |
|---|---|---|
| Visual design | Authored hierarchy, Persian typography, meaningful art/motion, deliberate mobile composition and a coherent family across both products | Before/after real routes, interaction recordings and a reference comparison identifying concrete wins/gaps; independent review and prepared owner visual disposition |
| Usability | A visitor understands the offer and completes the intended path without duplicate forms, dead ends, hidden actions or preventable data loss | Actual FA/EN journey tests with keyboard/touch, Back, failure/retry and both candidate apps; clicks are not successful requests |

| Accessibility | WCAG 2.2 AA as the target, including semantics, focus, keyboard, contrast, zoom/reflow, RTL/LTR, status/error announcements and reduced motion | Automated axe plus manual route/state checklist; zero unresolved applicable AA failures. An automated score alone is not conformance |
| Performance | Documented lab profile: median LCP ≤2.5s, max CLS ≤0.1 and max sampled interaction latency ≤200ms across three comparable runs; existing stricter ASDEV JS/GPU/lifecycle budgets remain | Every raw run, network/CPU/browser/build/profile and before/after bytes; report p75 field LCP ≤2.5s, INP ≤200ms, CLS ≤0.1 separately when sufficient field data exists |

## Technical SEO and content rules

- Inventory public/indexable, public/noindex and private/authenticated routes, including query/filter variants. Serve important copy and links as semantic HTML; canvas/animation is enhancement. Keep metadata in the existing Next.js helpers.
- Sitemaps contain only intended, canonical, published, successful public pages, with truthful modification dates. No localhost/staging, token reports, comparisons, accounts/admin, success/failure utility pages or arbitrary search variants.
- Private access is enforced at the application boundary. `robots.txt` and `noindex` are not security controls. Crawlers cannot read a noindex directive on a robots-blocked URL; handle public utility exclusions deliberately and never expose private data just to let a crawler read metadata.
- Use honest page titles/descriptions and appropriate visible headings. Structured data must match visible facts and an eligible type; no fake ratings, invented credentials, fabricated authors, or promise of a rich result. More schema is not automatically better.
- Each content item has an audience question, owner URL, distinct answer, evidence/example, author/reviewer, actual update date, limits and one useful next action. Start by improving relevant existing pages. No arbitrary word-count target, keyword stuffing, scraped/rephrased competitor articles, auto-published AI bulk pages, fake freshness, doorway cities or bought links.
- Prepare factual helpful material and linkable examples. Sending outreach, buying ads/links, changing prices, launching campaigns or publishing new commercial promises requires actual applicable authorization. Repository content preparation is not a claim of production publication.

## Measurement and leadership evidence

Use existing analytics and consent behavior first. Before enabling any new live collection, review what is collected, permission, retention and removal. Do not require a new paid tool or analytics provider. If Search Console/analytics access is absent, complete local technical work and a reusable import/report path using clearly labeled test data; keep actual business outcomes UNVERIFIED. Never make up impressions, conversions or query volume.

Minimum scorecard per product: intended/indexed URL coverage; non-brand impressions and clicks; CTR with impressions; query cohort's observed top-10/top-3/#1 presence; qualified enquiry or successful useful audit completion rate with denominator; return usage if consented and observable; field CWV; error/timeout rate; and content freshness/quality gaps. Keep brand versus non-brand, mobile versus desktop, FA versus EN, and geography distinct. Record missing/anonymized queries and source limits. Average Search Console position is an aggregate observation, not a universal live rank.

Targets: first qualify the cohort and establish baseline; improve qualified task completion and relevant search visibility; then pursue top-10, top-3 and #1 for those verified intents while maintaining product quality. Do not invent a percentage growth target before baseline. A dated single-query #1 observation supports only that observation. A leadership claim needs named queries/market/device, repeated observations across at least two non-overlapping 28-day windows and an honest account of misses; never generalize it to “world #1.”

For a growth change, record hypothesis, changed URLs, primary metric, guardrails, comparison window, sample-size limitation and keep/revert decision. Review comparable 28-day windows when available, allowing indexing and seasonality effects. Small samples permit description, not causal conversion claims. Fix visible defects immediately; do not run underpowered A/B tests simply to produce activity.

## Bounded execution and closure

First finish safe dependency-ready implementation and acceptance tasks. Then perform one evidence-based growth review using the data available; prepare the next measurable action only if it addresses an observed gap within this mission. Waiting for traffic, an owner disposition, credentials or a future observation is **not** an infinite CLI loop.

At no remaining safe ready work, save an exact checkpoint and end with either `IMPLEMENTATION_ACCEPTED`, `RELEASE_VERIFIED`, `BLOCKED` or `AWAITING_OBSERVATION` **with scope and evidence**; never use one label for the whole program if other dimensions are pending. A new run resumes the same queue from changed evidence. Do not create cron jobs, timers, recurring messages or external monitors merely because this mission uses the word “loop.”
